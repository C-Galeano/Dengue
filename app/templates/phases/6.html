A smart-hospital module for the first consultation

This Flask application is the deployment. The clinician registers a febrile patient and, in seconds, gets the probability of each arbovirus, the suggested diagnosis, why the model suggests it, and the next steps.

Design decisions

  • Explanations without extra weight: XGBoost and LightGBM compute exact SHAP values natively, so the server does not need the shap package.
  • One artifact: models/model.pkl holds the model, threshold, labels and metrics; it is loaded once at startup.
  • Same features everywhere: src/preprocessing.py builds the patient row exactly like the training data.
  • Flexible storage: findings, probabilities and explanations are saved as JSON, so adding a field does not require a database migration. SQLite locally, PostgreSQL in production via DATABASE_URL.
  • Server-side validation and Post/Redirect/Get (reloading never registers twice).
  • Pinned versions of scikit-learn {{ info.versions['scikit-learn'] }}, XGBoost {{ info.versions.xgboost }} and LightGBM {{ info.versions.lightgbm }}, the ones used in training.
  • Mandatory notice on every page: decision support only.

Monitoring and maintenance

  • Retrain each year with python -m src.sinan and python -m src.train. The current model was trained on {{ info.trained_at[:10] }}.
  • Watch for drift: compare the share of each suggested diagnosis with the circulation reported by the surveillance system; a large gap means the model must be reviewed.
  • Close the loop: store the laboratory result of each consultation, so the hospital builds its own labeled dataset (with numeric lab values) for the next iteration.
